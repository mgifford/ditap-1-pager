# AGENTS.md  
DITAP Curriculum Update Project

## Purpose of This File

This repository may be worked on by automated agents and human contributors.

This file defines non-negotiable principles, accessibility expectations, and procurement values that must guide all contributions, including code, content, tests, documentation, and design decisions.

If an agent or contributor cannot comply with these requirements, it should not proceed.

---

## Project Mission

The DITAP Curriculum Update exists to ensure that procurement training reflects:

- Current Federal Acquisition Regulation (FAR) requirements
- Modern digital services procurement practices
- Outcomes-based and performance-based acquisition
- Defensible, transparent decision-making

The goal is not novelty.  
The goal is competent, compliant procurement that delivers real outcomes.

---

## Primary Audience

The primary audience for all outputs is:

- Procurement officers
- Contracting officers
- Acquisition professionals
- Program and technical staff involved in procurement decisions

Assume the audience is:
- Experienced
- Time-constrained
- Policy-literate
- Skeptical of buzzwords
- Accountable for decisions

Write and build accordingly.

## Accessibility Principles (Mandatory)

Accessibility is a baseline requirement, not an enhancement.

All work must aim to meet WCAG 2.2 AA in practice.

### Required Accessibility Practices

Agents and contributors must:

- Use semantic HTML and proper landmarks
- Maintain a logical heading structure
- Ensure full keyboard operability
- Provide visible focus indicators
- Label all form controls programmatically
- Maintain sufficient color contrast
- Include skip links where appropriate

### Testing Expectations

- Automated accessibility testing is required where feasible
- Tests must fail on detectable accessibility violations
- Automated tests reduce risk but do not replace human review

### Explicit Prohibitions

Do not introduce:
- Accessibility overlays
- Automated fixer widgets
- Claims of certification or guaranteed compliance

Accessibility failures are considered functional defects, not cosmetic issues.

## Procurement Values and DITAP Principles

All contributions must align with the core values DITAP promotes.

### Fair Procurement

- Avoid language or designs that privilege specific vendors or tools
- Emphasize capability, outcomes, and compliance over brand or platform
- Ensure materials support fair competition

### Equitable Procurement

- Recognize that procurement decisions affect who can participate
- Avoid unnecessary barriers to entry, complexity, or opacity
- Support procurement approaches that broaden access to opportunity

### Transparent Procurement

- Favor clarity over cleverness
- Make assumptions explicit
- Document rationale for decisions
- Avoid hidden logic or unexplained constraints

If a procurement officer cannot reasonably explain a decision based on the material produced here, the work is incomplete.

---

## Outcomes-Based Focus

DITAP emphasizes outcomes-based procurement.

Contributors and agents must:

- Focus on results rather than inputs
- Avoid checklist-driven or compliance-only framing
- Emphasize how contracts are structured, evaluated, and managed over time
- Reflect current FAR-aligned practices

Avoid nostalgia for outdated procurement models.

---

## Tone and Language Requirements

All content must be:

- Plain language
- Direct
- Precise
- Policy-aware

Avoid:
- Marketing language
- Jargon without definition
- Abstract claims without implications
- Unverifiable assertions

Assume scrutiny. Write defensibly.

## Agent Behavior Expectations

Automated agents working in this repository must:

- Follow this file as binding instruction
- Prefer small, reviewable changes
- Avoid introducing unnecessary tooling or abstraction
- Flag uncertainty rather than inventing answers
- Optimize for clarity, accessibility, and defensibility

If tradeoffs are required:
1. Accessibility wins
2. Clarity for procurement officers wins
3. Long-term maintainability wins
4. Convenience for the contributor loses

---

## Definition of Acceptable Work

Work is acceptable only if:

- It supports fair, equitable, transparent procurement
- It aligns with modern FAR expectations
- It improves clarity for procurement officers
- It does not introduce accessibility regressions
- It can be defended in a compliance or audit context

If a contribution cannot meet these criteria, it should not be merged.
